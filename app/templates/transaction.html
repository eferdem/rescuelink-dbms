The seven steps

  1. BEGIN
  2. SELECT … FOR UPDATE locks the batch row
  3. Validate status, expiry and remaining quantity
  4. INSERT batch_allocations
  5. INSERT cold_chain_checks and guard the probe
  6. INSERT delivery_runs, run_batches, shift_assignments (licence check)
  7. UPDATE donation_batches, INSERT audit_log, COMMIT

If any step fails, the handler issues ROLLBACK and the row counts below prove that nothing survived. Try the slow lock mode in two browser tabs to see the second coordinator block on the row lock.

Transaction isolation: PostgreSQL default (READ COMMITTED). The row lock is what prevents two coordinators from over-claiming the same batch.
